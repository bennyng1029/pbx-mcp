### Task 1: AMI reliability: shared connect, login-gated ready, bounded calls, no false empties

Depends on Task 0

State: concurrency

Files: `src/lazy-client.ts` (new, extracted from `lazyClient` in `src/index.ts`); `src/index.ts` (import it, no behaviour change beyond the fix); `src/ami.ts` (`connect()`, `close()`, `action()`); `src/tools/asterisk.ts` (`asterisk_channels`, `asterisk_endpoints`, `asterisk_hangup_preview`); `src/tools/format.ts` (only if a shared helper is needed); `test/helpers/mock-ami.mjs` (add `requireLogin`, `loginDelayMs`, `errorFor`, `omitComplete`, channel and endpoint fixtures); `test/ami-reliability.test.mjs` (new); `docs/verification/task1.md` (new, live re-check).

Approach: Extract `lazyClient` to `src/lazy-client.ts` so it is importable by tests (`src/index.ts` has top-level side effects); this is the minimum change needed for reuse (Rule 19 exception) and `src/index.ts` keeps both the Asterisk and FreeSWITCH callers. The holder keeps one in-flight connect promise and all concurrent callers await it; a client is handed out only once its `connect()` resolves and, once awaited, the holder re-checks `isConnected` and retries the connect once if the socket already dropped. The holder tags each attempt with a generation and applies a result (ready or failed) only if its generation is still current, so a late rejection of an old attempt cannot clear newer state. In `AmiClient.connect()` (`src/ami.ts`): the outer promise also rejects on socket `close` and `error` before login completes (today `destroy()` from `close()` leaves it pending forever in the TCP phase); `connected` becomes true only once the Login response is Success and only if the client was not closed meanwhile (a Login success racing an explicit `close()` must not publish a ready client); connect + login share one budget of `timeoutMs` (the Login `action()` receives the remaining time, so the worst case is not 2x); `close()` during connect rejects the pending connect. Lists: a first message `Response: Error` becomes `AmiError(Message)` through a small helper next to `listRows` in `src/ami.ts`, never an empty list. In `action()`, a timeout following an `EventList: start` header was seen but no `...Complete` event arrived now rejects with an "incomplete list" error and removes its waiter (it no longer hands back partial rows silently); a timeout with a lone Response keeps today's behaviour. Multi-step tools have an overall budget: `asterisk_endpoints` (PJSIP then chan_sip fallback) completes within `2 x timeoutMs` once connected (3x including a cold connect); `asterisk_endpoints` replaces the bare `catch` with: PJSIP not loaded (Error that says no such command/module) -> try chan_sip; other Error -> tool error; Success with zero rows -> "PJSIP loaded, 0 endpoints". Test-coverage target: see Success criteria. Architecture-fit target: the holder stays generic (`T extends {connect, close}`) so `EslClient` is unaffected; `src/ami.ts` remains the one canonical AMI module (Rule 18).

Invariants:

| State | Event / guard | Result | Side effects |
|---|---|---|---|
| none | caller arrives | create client, generation g, state = connecting(g,p), await p | 1 socket opened |
| connecting(g,p) | another caller arrives | await the same p | 0 sockets, 0 `close()` |
| connecting(g,p) | Login Success and client not closed | state = ready(g,c), `connected=true` set here only | none |
| connecting(g,p) | Login Success but `close()` ran first | reject p, state stays none | client closed once |
| connecting(g,p) | socket close/error, timeout, or Login rejected | state = none, every waiter rejects with the same error | client closed once |
| late event for generation g' != current | any result of an old attempt | ignored | none |
| ready(g,c) | caller, `c.isConnected` | return c | none |
| ready(g,c) | caller, socket has dropped | state = none, new connecting(g+1,p') | old client closed once |

Hand-trace, three parallel cold calls A, B, C: A finds none, creates p (1 socket). B and C find connecting(p) and await it (no `close()` on A's client, which is the defect today). Login Success resolves p, all three receive the same client with `connected=true`. Total sockets 1, `close()` calls 0. Against the old code there are two defects. (a) If B arrives during A's TCP-connect window, B's `alive` check is false, so it calls `A.close()`, which destroys A's socket without an `error` event (only `close`) and A's connect promise never settles. (b) If B arrives following the TCP connect but before Login completes, `connected` is already true, so B receives the not-yet-authenticated client and sends its action first (the lab answers `Response: Error`, `Message: Permission denied`, probed 2026-10-03). During the Login phase a closed client does not hang forever: `close()` clears the waiters and the `action()` timer rejects following `timeoutMs`.

Assumptions: Asterisk answers an unauthenticated action with `Response: Error` (probed on the lab). `EslClient.connect()` resolves only when authenticated (esl.ts:63-74), so the shared-promise change is neutral for FreeSWITCH.

Risks: the holder is shared with FreeSWITCH (a behaviour change there is a defect: covered by a test with a stub client); the connect deadline is the existing `PBX_MCP_TIMEOUT_MS`, default 10 s; rejecting incomplete lists can turn a previously "usable" partial answer into an error on a flaky link, which is the intended change.

Decision points: none beyond the spec.

External dependencies: none.

### Task 2: Targets: file loader, registry, select/list/get tools, read-only enforcement

Depends on Task 1

Files: `src/targets.ts` (new); `src/config.ts` (add `targetsFile`, `hostAllow`, `adhocPorts`; accept targets without `ASTERISK_AMI_HOST`); `src/index.ts` (build the registry; register Asterisk tools and provisioning whenever any Asterisk target exists or `PBX_MCP_HOST_ALLOW` is set); `src/tools/targets.ts` (new: `pbx_list_targets`, `pbx_select_target`, `pbx_get_target`); `src/tools/asterisk.ts` (snapshot-based read-only check, status header); `test/targets.test.mjs` (new).

Approach: `src/targets.ts` exports `loadTargets(env)` and `TargetRegistry`. The JSON file (`PBX_MCP_TARGETS_FILE`) has `targets{name: {host, port?, tls?, username, password | passwordEnv, label?, readOnly?, provision?, pjsipFile?, trunkAllow?, contextAllow?, dialplanHint?}}` with strict zod objects (zod is already a dependency) and no `default` key. Env-only config (`ASTERISK_AMI_*`) becomes the target named `default`; when both env credentials and a file exist, the targets are `default` plus the file targets and selection is required; a file target named `default` is rejected. A single configured target is selected implicitly. `passwordEnv` is resolved at load; a literal password in a file readable by group/other logs a stderr warning; neither start-up nor tool errors echo a password or env value. Gates for file targets: `provision` defaults to false and `trunkAllow`/`contextAllow` default to empty; only the env-only `default` target takes the global `PBX_MCP_ALLOW_PROVISION`, `PBX_MCP_TRUNK_ALLOW`, `PBX_MCP_CONTEXT_ALLOW`, `PBX_MCP_PJSIP_FILE` values. `pjsipFile` is validated at load, only for targets with `provision` true, by calling the existing validator in `src/provision.ts` from the loader (no duplicate), so a bad value fails start-up. The registry owns one lazy client per target (Task 1's holder) and at most one live ad hoc client (selecting another ad hoc target closes the previous one and deletes its holder entry; a snapshot's `getClient` is bound to its own holder and, once evicted, rejects with "target no longer selected" and never reconnects). `Snapshot = {name, label, host, port, dialplanHint, readOnly, getClient: () => Promise<AmiClient>}`. It exposes `snapshot()` (synchronous; throws `no_target_selected` when none is selected, which write tools turn into a tool error before any AMI action), an immutable `{name, label, host, port, dialplanHint, readOnly, getClient}` bound to one target and read synchronously, and `identity()` (the same without `getClient`, no secrets). `getClient()` keeps the existing `() => Promise<AmiClient>` signature, reads the current target synchronously before its first await, and throws text `no_target_selected` when none is selected. `pbx_select_target` takes `{name}` XOR `{host, port?, tls?}` with strict schemas (extra keys such as `username`, `password`, `trunkAllow` are rejected) and assigns the selection synchronously, so an earlier select can never overwrite a later one. Ad hoc policy: `host` must be an IP literal (`net.isIP`, no zone id; IPv4-mapped IPv6 normalized) inside a CIDR of `PBX_MCP_HOST_ALLOW`; hostnames are not accepted for ad hoc (use a named target); the port must be in `PBX_MCP_ADHOC_PORTS` (default `5038`); an empty allowlist or absent default env credentials refuses ad hoc; ad hoc targets use the default env credentials, are always read-only, and have no provisioning gates. TLS verification stays disabled as in the existing code (documented limitation). Read-only enforcement: `registerAsteriskTools` gains an optional trailing parameter `getSnapshot` (synchronous `() => Snapshot`; the default, used when the parameter is omitted, returns `{readOnly:false, getClient: <the existing positional getClient>}` so existing callers are unchanged); `asterisk_originate`, `asterisk_hangup` and `asterisk_cli` call `getSnapshot()` once at entry, refuse before any AMI action if `snapshot.readOnly`, and use that same snapshot's `getClient` (CLI policy uses `write && !snapshot.readOnly`), so a selection change between check and use cannot redirect a write. `asterisk_status` prints its target header from the same snapshot it uses for the client. `pbx_list_targets` shows name, label, host, port, readOnly and provision flag, never a secret. Test-coverage target: see Success criteria. Architecture-fit target: `src/targets.ts` is the one place target settings are resolved (Rule 18); tools receive a snapshot, never raw credentials.

Assumptions: selection state lives in server process memory; one MCP client per server process (stdio). `src/tools/provision.ts` is edited in Task 3 only. A deployment with only `PBX_MCP_HOST_ALLOW` set is supported: the tools register and return `no_target_selected` until an ad hoc target is selected.

Risks: a malformed file must fail fast at start-up with a clear message; switching targets leaves earlier named-target connections open until exit (bounded by the number of named targets); the one-ad-hoc-client rule closes the previous ad hoc connection on switch.

Decision points: none; the owner confirmed the target model and ad hoc read-only in session. Simplifications (hostnames only via named targets, one ad hoc client) are recorded in the header paragraph.
