### Rule 6a locked decisions (verbatim from `docs/plans/multi-target.decisions.md`)

# Rule 6a locked decisions: multi-target wave (approved by the owner 2026-10-03)

1. **Write permission** = global `PBX_MCP_ALLOW_WRITE` AND the selected target permits writes, decided on one `Snapshot` taken at tool entry (originate, hangup, write CLI, and the four provisioning mutators). Why: a selection change between check and use must not redirect a write. Reverse: remove the snapshot check (not recommended).
2. **Ad hoc targets** are always read-only; host = IP literal inside a `PBX_MCP_HOST_ALLOW` CIDR, port in `PBX_MCP_ADHOC_PORTS` (default 5038), default env credentials, at most one live ad hoc client; hostnames only via named targets. Credentials and gates are never tool arguments (strict schemas).
3. **Explicit `target` argument** on `asterisk_trunk_create/delete` and `asterisk_extension_create/delete`: required when more than one target exists, must equal the selected target, else refused with zero AMI writes. Owner-approved addition beyond the original request.
4. **Gates are operator-owned.** File targets default to `provision: false` and empty allowlists; only the env-only `default` target uses the global `PBX_MCP_*` values. A `readOnly` target also refuses provisioning. One `Provisioner` per named target, built at load with that target's client and gates (keeps its write queue).
5. **Reliability.** One shared in-flight connect per holder with a generation guard; `connected` only after Login success; connect + login share one `timeoutMs`; a list that saw `EventList: start` and no Complete event rejects as incomplete; `Response: Error` is a tool error, never an empty list.
6. **Config surface.** `PBX_MCP_TARGETS_FILE` (optional JSON, strict), `PBX_MCP_HOST_ALLOW`, `PBX_MCP_ADHOC_PORTS`; env-only setups behave identically (implicit target `default`); a file target named `default` is rejected; no `default` key in the file.
7. **Scope.** Asterisk only (FreeSWITCH untouched); no CDR view (backend is `cdr-custom` file, unreadable over AMI); no new third-party dependency (Rule 17: none requested, none approved).
8. **Accepted limitation.** AMI is plaintext on 5038 and TLS verification stays off as today; ad hoc credentials are for trusted lab networks only; keep `PBX_MCP_HOST_ALLOW` narrow.
9. **Rule 23.** Lab writes in Tasks 0, 4 and 6 are confirmed by the owner for the lab Asterisk 192.168.10.244 (mt-answerer) only, `vfy-*` objects only, deleted afterwards. The confirmation does not carry to any other target. The server cannot enforce this; it is a process rule.
10. **Verification.** sipclient-mcp drives calls; SIPp / raw AMI scripts / `tcpdump` only where it cannot (Rule 21: capture wins). Baseline (Task 0) before any change, final (Task 6) after the last task.
11. **Branch.** `feat/multi-target` off `feat/provisioning`.
